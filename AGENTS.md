# AGENTS.md

## Purpose

Build and maintain Chronicle (TanStack Start + React + TypeScript + Prisma/SQLite) with minimal, safe, reviewable changes.

Chronicle is a personal journal app: authenticated users write dated rich-text entries, tag them, and browse them by month, date, or tag.

## Core Rules

- Keep changes small and focused on the user request.
- Prefer existing patterns over introducing new abstractions.
- Do not edit generated files.
- Run validation after meaningful edits.
- Never manually fix lint or formatting errors that can be autofixed; run the file-scoped autofix (see Commands) on touched files first and only hand-fix what remains.
- If behaviour is unclear, inspect nearby code before implementing.

## Stack

- Node 24 (`.nvmrc`), Yarn 4 (do not use npm/pnpm; `README.md` is stale template text and mentions pnpm).
- TanStack Start (SSR via Vite + Nitro), TanStack Router (file-based), TanStack Query, TanStack Form.
- Prisma 7 with `prisma-client` generator and the `better-sqlite3` driver adapter.
- Auth: `better-auth` (email + password), using the Prisma adapter.
- UI: Tailwind CSS v4, shadcn/ui (`base-vega` style, Base UI primitives, lucide icons), Tiptap rich-text editor, `sonner` toasts.
- Validation: `zod` v4. Dates: `dayjs` (preferred; `date-fns` is only used by `react-day-picker`). Logging: `pino`.

## Commands (Yarn 4)

- Install deps: `yarn install`
- Dev server: `yarn dev` (http://localhost:3001)
- Build: `yarn build`
- Run production build: `yarn start`
- Tests: `yarn test` (Vitest + Testing Library + jsdom; no tests exist yet)
- Lint: `yarn lint`
- Format: `yarn format`
- Autofix lint + format (touched files only, preferred): `yarn prettier --write <files> && yarn eslint --fix <files>`
- Autofix lint + format (whole repo): `yarn check` (avoid in task-driven changes; it reformats unrelated files)
- Type check: `yarn tsc --noEmit`
- Prisma Studio: `yarn db:studio`

A Husky pre-commit hook runs `lint-staged` (prettier + eslint on staged files).

## Environment

- Copy `.env.template` to `.env.local`. All `db:*` scripts load `.env.local` via `dotenv-cli`.
- Required: `DATABASE_URL` (SQLite file, e.g. `file:./dev.db`), `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (defaults to `http://localhost:3001`).
- Never commit `.env*` files or `dev.db`.

## Database Workflow

- Uses Prisma + SQLite.
- Change schema in `prisma/schema.prisma`.
- Then run:
  1.  `yarn db:generate`
  2.  `yarn db:migrate` (or `yarn db:push` for local iteration)
  3.  `yarn db:seed` if seed data needs updates
- There is no `prisma/migrations` directory yet; the database has been managed with `db:push`. Ask before introducing the first migration.
- `User`, `Session`, `Account`, and `Verification` models are owned by better-auth; keep them compatible with its expected schema.
- Tables are mapped to lowercase names via `@@map` (e.g. `entry`, `tag`); use those names in `$queryRaw`.

## Architecture & Patterns

### Routing

- `_authed/` routes are protected by `authMiddleware` in `src/routes/_authed/route.ts` (redirects to `/login`). `_unauthed/` holds login/register.
- Entries are browsed via `/entries/by/$contextType/$contextId/$entryId`, where `contextType` is an `EntryContextType` (`month` | `date` | `tag`) from `src/features/entries/types.ts`. Context IDs are `YYYY-MM` (month), `YYYY-MM-DD` (date), or the tag text.
- Files prefixed with `-` in `src/routes` (e.g. `-not-found.tsx`) are excluded from routing.
- Server-only HTTP endpoints use `server.handlers` on a file route (see `src/routes/health.ts`, `src/routes/api/auth/$.ts`).

### Data access

- Server functions live in `src/features/<feature>/data/*.ts`, one per file, built with `createServerFn()`.
- Every user-data server function must use `.middleware([authMiddleware])` and scope queries by `context.session.user.id` (e.g. `where: { authorId: userId }`).
- Validate input with `.validator(...)`, preferably a zod schema from `src/features/<feature>/lib.ts`.
- Declare explicit return types on handlers (e.g. `Promise<EntryWithTags>`).
- Route data is usually loaded in a route `loader` and read with `Route.useLoaderData()`. After mutations, call `router.invalidate()`.
- Where TanStack Query is used, colocate a `use...Query` hook with the server function and wrap it with `useServerFn`.
- `src/lib/error-handler-middleware.ts` is global function middleware: it logs errors and converts Prisma `P2025` (record not found) into `notFound()`, so `findUniqueOrThrow` / `update` with a missing row results in a 404.
- Raw SQL aggregation uses `prisma.$queryRaw` with tagged templates. Never use `$queryRawUnsafe` with user input.

### Forms & UI

- Forms use TanStack Form (`useForm`) with zod validators and shadcn `Field` components (see `src/features/entries/components/entry/edit/index.tsx`).
- Add shadcn components with `yarn dlx shadcn@latest add <component>`. Follow the rules in `.agents/skills/shadcn/SKILL.md` (semantic colors, `gap-*` not `space-*`, `cn()` for conditional classes, and so on).
- Use `assertUnreachable` from `~/lib/utils` for exhaustive `switch` over enums.
- Date formatting helpers are in `src/lib/dates.ts`.

## Coding Conventions

- TypeScript first; keep types explicit at boundaries. `strict`, `noUnusedLocals`, and `noUnusedParameters` are enabled.
- Import from `src` with the `~/` alias (e.g. `~/components/ui/button`). Use relative imports only for siblings within a feature folder.
- ESLint enforces import ordering: builtin, external, then internal (`~/`), then parent/sibling. Groups are separated by blank lines and sorted alphabetically. The file-scoped autofix fixes ordering automatically, so don't reorder imports by hand.
- Prettier: no semicolons, single quotes, trailing commas, Tailwind class sorting.
- File names are kebab-case. Components are `React.FC` or function components with named exports.
- Reuse helpers in `src/lib/utils.ts` and existing UI primitives before adding new ones.
- Follow current route and feature organization.
- Keep server/client concerns separated per existing route patterns.
- Avoid unrelated refactors in task-driven changes.

## Pre-Completion Checklist

- Relevant tests pass (at least targeted scope).
- File-scoped autofix has been run on touched files, and lint passes for them.
- Type check passes (`yarn tsc --noEmit`).
- No generated files manually modified.
- Imports and naming follow existing conventions.
- Any schema change includes generated/migration follow-through.
- New server functions that touch user data use `authMiddleware` and are scoped to the current user.
